Data cleaning guide

Remove duplicate customers in a CSV, including the ones spelled differently

Exact copies are easy. The real problem is Acme Inc, ACME INC. and Acme, Inc, which any exact comparison counts as three customers. The fix has three parts: clean each name into a matching key, find duplicates on the key, then review the borderline pairs by hand. Never delete on a similarity score alone.

Updated 4 November 2026. Examples on this page were run for real; the data in them is made up.

Comparing the original text exactly, we found 0 duplicates. After building the key, the five Acme rows collapse into one, and the two Beta Traders rows into one. That leaves four distinct keys. beta traders and beta trader still differ by one letter. Whether they are the same business is a question about the world, not about the text, so that pair goes to review.

Step 1: build a matching key

Never edit the original name column. Add a new one for the key. The key should be lower case, with punctuation removed, repeated spaces collapsed and company suffixes written one way. In Excel or Google Sheets:

=LOWER(TRIM(SUBSTITUTE(SUBSTITUTE(SUBSTITUTE(A2,",",""),".",""),CHAR(160)," ")))

The CHAR(160) part matters. Text copied from web pages often contains non-breaking spaces, and Excel's TRIM does not remove those. A name can look clean and still fail to match. We tested this formula on the example, including a name with a non-breaking space, and all five Acme spellings came out as acme inc. Writing "Incorporated" as "inc" took one more replacement.

Step 2: flag duplicates on the key

=COUNTIF($B$2:$B$500,B2)>1

Filter for TRUE. Do this before deleting anything, so you can look at each group. Then check how your tool treats letter case. Trailing spaces and punctuation are the bigger trap: they make two identical-looking names different, and exact-match tools will not warn you.

Step 3: review near matches, with a second field

A similarity score only produces candidates. In Python, the standard library can rank them:

import difflib
difflib.SequenceMatcher(None, "beta traders", "beta trader").ratio()   # 0.96
difflib.SequenceMatcher(None, "acme inc", "gamma llc").ratio()         # 0.24

A score of 0.96 says "look at this pair". It does not say "merge". Pick a threshold by looking at real pairs in your own file: set it low and you will merge different companies, set it high and you will miss real duplicates. For each candidate pair, check a field that is hard to mistype, such as email domain, phone number, tax or registration ID, or address. Same name and same tax ID: merge. Same name and different tax ID: probably two businesses.

Step 4: decide which row to keep

  • Keep the row with the most complete fields, or the most recently updated one, and say which rule you used.
  • Copy useful values from the other rows (a phone number, a second address) before dropping them.
  • Move the removed rows to a separate sheet instead of deleting them. If someone asks next month why a customer disappeared, you can answer.

Before you delete: is it a record or a transaction?

If each row is a customer, merging duplicates is right. If each row is an order or a payment, two identical rows may be two real sales. Deleting one changes your total. Check against an order or invoice ID before removing anything from a transaction list.

Questions people ask

Does Excel's Remove Duplicates find near matches?

No. It compares cell contents. Differences such as a trailing space, a full stop or a different suffix make two names count as different. Build a cleaned matching key column first and remove duplicates on that.

How do I find duplicates with slightly different spelling?

Clean the text into a key (lower case, no punctuation, single spaces), flag duplicates on the key, then rank the remaining pairs with a similarity score and review them by hand using a second field such as email or tax ID.

What similarity threshold should I use?

There is no universal number. Look at real pairs from your file near the cut-off. A lower threshold merges different companies by mistake, a higher one leaves real duplicates behind.

Is it safe to delete duplicate rows?

Only after you know whether rows are records or transactions. Two identical order rows can be two real orders. Move removed rows to another sheet so the change can be explained later.
