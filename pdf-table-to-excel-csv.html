PDF table to Excel or CSV: get rows you can actually use

Select the table in a PDF, paste it into Excel, and you usually get one long column of text or a grid with the columns in the wrong places. The fix is to read the table as rows and columns, join the pages, and clean the result before you use it. This page explains how that works and where it stops working.

Updated 4 November 2026. Examples on this page were run for real; the data in them is made up.

Why copy and paste breaks

A PDF is a picture of a page with text placed at exact positions. It has no idea what a row or a column is. When you copy from it, your spreadsheet has to guess, and it guesses badly in four predictable ways:

  • Columns collapse. The text of a whole row lands in one cell, or a two-word name such as Acme Inc is split across two columns.
  • Long cells wrap into extra rows. A description that runs onto a second line becomes its own row with only one cell filled.
  • Headers repeat on every page. A report of 300 rows over six pages brings six copies of the header into the middle of your data.
  • Numbers arrive as text. 1,234.50 and (500.00) look like numbers but will not add up. See numbers stored as text.

How a PDF table becomes rows and columns

There are two kinds of table in a PDF, and they are found in different ways.

KindWhat it looks likeHow it is read
RuledLines or borders around the cellsThe drawn lines mark the cell edges. This is the most reliable case.
BorderlessColumns that only line up by spacingThe reader looks for empty vertical strips that run down the page and treats them as column breaks.

After that, tables that continue on the next page with the same header are joined, so a six-page report comes back as one table with one header row. We tested this on a generated 80-row invoice list across three pages: it came back as 81 rows (header plus 80) in four columns, with no repeated headers.

What to fix afterwards

Reading the table is the first half. The second half is cleaning it, in this order:

  1. Trim spaces. Extra or non-breaking spaces make identical values look different.
  2. Remove empty rows and columns. Page breaks and spacing often leave blank ones behind.
  3. Join wrapped lines. A row with nothing in the first column but text elsewhere is usually the second line of the row above it.
  4. Turn text into numbers. Remove thousands commas and currency signs, and treat (500.00) as -500.00. Leave phone numbers and codes alone, because a leading zero is part of the value.
  5. Make dates one format. Write YYYY-MM-DD. A date such as 03/04/2026 can mean 3 April or 4 March, and only you know which. See mixed date formats.
  6. Remove duplicates last. Only after the text is comparable. See duplicate customers.

Questions people ask

How do I convert a PDF table to Excel?

Read the table as rows and columns instead of copying it, join the pages, clean the text and numbers, then save it as CSV, which Excel opens. In The God's Tool, open PDF to data, drop in the PDF and download the CSV.

Why does my PDF table paste as one column?

A PDF stores text at positions on the page, not as cells. Your spreadsheet has to guess where the columns are, and without cell lines it often guesses wrong.

Can it read a scanned PDF?

No. A scan is a picture with no text in it, so there is nothing to read. Use the original PDF from the program that created it.

What happens to a table that runs over several pages?

Pages that continue the same table with the same header are joined, and the repeated header rows are removed, so you get one table.

Is the PDF stored or sent to an AI?

No. The PDF is read on our server from its own text without AI and is not stored.

Will it get every table right?

No. Ruled tables read most reliably. Merged cells and irregular layouts can come out wrong, so check the result against the PDF.
