Data cleaning guide

Fix mixed and ambiguous dates in a CSV (is 03/04 March or April?)

If some date in the file has a first number above 12 (like 25/03/2026), the file proves its own order and you can convert it safely. If none do, the file cannot tell you, and you have to ask whoever exported it. Once the order is known, write every date as YYYY-MM-DD, because that form means the same thing in every country and every tool.

Updated 4 November 2026. Examples on this page were run for real; the data in them is made up.

Why dates break without any warning

A date like 03/04/2026 is two different days. In the US it means March 4. In the UK, India and most of Europe it means 3 April. When you open a CSV in Excel, Excel reads it using your computer's regional setting. The file never says which order it uses, so the wrong guess does not produce an error. It produces a perfectly valid date that is wrong, and it sits in your report until someone notices a payment dated in the future.

The second trap is that Excel only converts the dates it can read in your setting. On a US setting, 13/04/2026 cannot be a month-first date, so it stays as text, while 03/04/2026 beside it quietly becomes a real date. You end up with one column holding two kinds of value.

Step 1: let the file prove its order

You are looking for a value that can only be read one way. A first number above 12 cannot be a month, so the file is day first. A second number above 12 means month first. Here is a small made-up column:

ValueFirst numberSecond numberCan it be read both ways?
03/04/202634Yes
13/04/2026134No, day first
25/03/2026253No, day first
07/04/202674Yes
04/05/202645Yes
31/01/2026311No, day first
02/02/202622Same either way

Three values have a first number above 12 and none has a second number above 12, so this file is day first. That settles the four values that looked ambiguous on their own, because a file is normally written in one order throughout.

If you find both kinds, some first numbers above 12 and some second numbers above 12, the column is mixed. Two exports were probably pasted together. Split the rows by where they came from and convert each part with its own order. Do not pick one order for the whole column.

Step 2: count it in Excel or Google Sheets

This works when the dates are stored as text in the form dd/mm/yyyy or mm/dd/yyyy. Put the dates in column A starting at row 2. In B2 and C2, pull out the first and second numbers:

B2: =--LEFT(A2,FIND("/",A2)-1)
C2: =--MID(A2,FIND("/",A2)+1,FIND("/",A2,FIND("/",A2)+1)-FIND("/",A2)-1)

Fill both down, then count how many are above 12:

=COUNTIF(B:B,">12")
=COUNTIF(C:C,">12")

On the example above the first count is 3 and the second is 0. Day first. We ran these formulas on exactly that data to check them.

Step 3: convert, knowing the order

Excel, no formulas: select the column, then Data, Text to Columns, Next, Next, choose Date in step 3 and pick DMY or MDY from the list beside it. This only works on dates that are still text.

Excel or Sheets, with a formula for padded dd/mm/yyyy text:

=DATE(RIGHT(A2,4),MID(A2,4,2),LEFT(A2,2))

Python with pandas. Always pass the format. Without it, pandas reads 03/04/2026 as March 4. With dayfirst=True it reads April 3. Both are only guesses. With an explicit format a wrong assumption fails loudly:

pd.to_datetime(s, format="%d/%m/%Y")      # 03/04/2026 becomes 2026-04-03
pd.to_datetime(s, format="%m/%d/%Y")      # raises an error on 13/04/2026

That error is a gift. It means your assumption was wrong and you found out before the data went anywhere. See the pandas documentation for to_datetime for the details.

Step 4: write the result as YYYY-MM-DD

This is the form defined by ISO 8601. 2026-04-03 cannot be misread, and it sorts correctly even as plain text. Keep this form in anything that will be shared, imported or stored.

When no value is above 12

Sometimes every day in the file is 12 or lower. The file cannot settle it. These checks can help, but none is proof:

  • Row-per-day data. If there is one row per day, the right order is the one where neighbouring rows are one day apart. Read the wrong way round, they jump by a month at a time.
  • Sorted data. If the file is in date order, only one reading keeps the dates rising.
  • The source. A bank, a shop platform or a CRM usually documents the format, or you can export one record you know the date of.

For anything involving money or deadlines, ask the source. A guess that looks reasonable is the dangerous kind.

One thing that cannot be undone

If someone already opened the CSV in Excel on the wrong setting and saved it, the original text is gone. Excel may have turned 3 April into March 4 and written that into the file. Nothing downstream can tell which dates were flipped. Go back to the original export.

To stop it happening again, do not double-click the CSV. Use Data, From Text/CSV, and set the date column to Text so Excel leaves it alone until you decide.

Questions people ask

Is 03/04/2026 March 4 or April 3?

Both are valid. It is March 4 in the US and April 3 in most of the rest of the world. A single value cannot tell you. Look at the other dates in the same file: any first number above 12 means day first, any second number above 12 means month first.

Why does Excel change my dates when I open a CSV?

Excel reads the dates using your computer's regional setting, not the file's. If the setting and the file disagree, valid-looking dates come out wrong, and dates that can't be read stay as text. Import with Data, From Text/CSV and set the column to Text to avoid it.

What date format should I use?

YYYY-MM-DD, the ISO 8601 form. It means the same thing in every country and sorts correctly as plain text.

Can a tool work out the date order for me?

Only when the file contains proof, such as a day above 12. When every day is 12 or lower, nothing in the file settles it, and a tool that claims to know is guessing. Check with the source of the export.
